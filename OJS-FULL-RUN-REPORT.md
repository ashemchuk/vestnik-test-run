## 3. Подготовила пароли базы и Compose

openssl rand -hex 24
openssl rand -hex 24

```dotenv

```

```bash

```

```gitignore

Синтаксис `${...}` и чтение `.env` описаны в [документации Docker Compose](https://docs.docker.com/compose/how-tos/environment-variables/variable-interpolation/). 

Написала `compose.yaml` для совместного запуска OJS, MariaDB и Mailpit:

**Источники:** [спецификация Compose](https://docs.docker.com/reference/compose-file/services/), [образ MariaDB и его переменные](https://hub.docker.com/_/mariadb), [контейнеры PKP](https://github.com/pkp/containers). Наш файл написан под локальный стенд; он не скопирован целиком из инструкции PKP. Названия `db`/`ojs`/`mailpit` и настройки томов — наши решения; поля `services`, `image`, `volumes`, `ports`, `depends_on` — синтаксис Docker.

```yaml
name: vestnik-ojs

services:
  db:
    image: mariadb:11.8
    environment:
      MARIADB_DATABASE: ojs
      MARIADB_USER: ojs
      MARIADB_PASSWORD: ${OJS_DB_PASSWORD:?Set OJS_DB_PASSWORD in .env}
      MARIADB_ROOT_PASSWORD: ${DB_ROOT_PASSWORD:?Set DB_ROOT_PASSWORD in .env}
    volumes:
      - db_data:/var/lib/mysql
    healthcheck:
      test: [CMD, healthcheck.sh, --connect, --innodb_initialized]
      interval: 5s
      timeout: 5s
      retries: 30
    restart: unless-stopped

  ojs:
    image: pkpofficial/ojs:3_5_0-5
    platform: linux/amd64
    user: "0:0"
    environment:
      SERVERNAME: localhost
      PKP_CONF: /var/www/html/config.inc.php
      PKP_CLI_INSTALL: "0"
      OJS_DB_PASSWORD: ${OJS_DB_PASSWORD}
    ports:
      - "127.0.0.1:8080:80"
    volumes:
      - ojs_app:/var/www/html
      - ojs_files:/var/www/files
      - ./docker/bootstrap.php:/opt/vestnik/bootstrap.php:ro
      - ./docker/php.ini:/usr/local/etc/php/conf.d/vestnik.ini:ro
      - ./docker/apache-local.conf:/etc/apache2/conf-enabled/vestnik-local.conf:ro
    command: [sh, -c, "php /opt/vestnik/bootstrap.php && chown www-data:www-data /var/www/files && exec /usr/local/bin/pkp-start"]
    depends_on:
      db:
        condition: service_healthy
      mailpit:
        condition: service_started
    restart: unless-stopped

  mailpit:
    image: axllent/mailpit:latest
    ports:
      - "127.0.0.1:8025:8025"
    environment:
      MP_DATABASE: /data/mailpit.db
    volumes:
      - mail_data:/data
    restart: unless-stopped

volumes:
  db_data:
  ojs_app:
  ojs_files:
  mail_data:
```

`platform: linux/amd64` использован для выбранного образа на ARM64. Своего образа не собирали. Тома отдельно сохраняют базу, приложение, рукописи и тестовую почту.

## 4. Настроила PHP, Apache и config.inc.php

Создала `docker/php.ini` с локальными настройками PHP:

**Зачем:** увеличить лимит загрузки и POST, задать память, время выполнения и часовой пояс. Выбранные числа — параметры нашего теста, а не обязательные значения OJS. **Без отдельного файла:** оставить настройки образа по умолчанию либо изменить основной `php.ini`/включить настройки в собственный образ. Через UI OJS серверные лимиты PHP не меняются. **Источники:** [директивы PHP](https://www.php.net/manual/en/ini.core.php), [настройка часового пояса](https://www.php.net/manual/en/datetime.configuration.php), [загрузка дополнительных INI-файлов](https://www.php.net/manual/en/configuration.file.php). Подключение файла в `conf.d` — механизм PHP, не особенность OJS.

```ini
upload_max_filesize = 64M
post_max_size = 80M
memory_limit = 256M
max_execution_time = 120
date.timezone = Asia/Novosibirsk
```

Создала `docker/apache-local.conf` для настройки Apache:

**Зачем:** исправить найденную ошибку запуска mutex и задать `ServerName localhost`. **Без отдельного файла:** внести директивы в основной конфиг Apache или подготовить собственный образ; при отсутствии ошибки можно использовать штатный механизм mutex. Переключение только PHP/OJS-настроек эту проблему не решает. **Источник:** официальное описание [директивы Apache Mutex](https://httpd.apache.org/docs/2.4/mod/core.html#mutex). Это настройка веб-сервера; OJS не требует файл с таким названием.

```apache
# File-based mutexes work under AMD64 emulation in ARM64 Colima.
Mutex fcntl:/var/lock/apache2 default
ServerName localhost
```

**Проблема:** Apache не мог создать mutex и не запускался. **Решение:** переключили механизм блокировок на `fcntl`. Причина сбоя именно в разнице архитектур не доказана.

Написала `docker/bootstrap.php`, который однократно подготавливает конфигурацию OJS:

**Зачем:** задать базу, SMTP, адрес и приватный каталог файлов, создать секреты и сохранить изменения перед браузерной установкой. 
**Без него:** вручную отредактировать `config.inc.php` на основе шаблона OJS и подключить готовый конфиг к контейнеру; затем пройти штатный установщик. Сам установщик остаётся нужен и при нашем bootstrap. 
**Источники:** имена секций и параметров — [config.TEMPLATE.inc.php именно OJS 3.5.0-5](https://github.com/pkp/ojs/blob/3_5_0-5/config.TEMPLATE.inc.php); получение случайных байтов — [PHP random_bytes](https://www.php.net/manual/en/function.random-bytes.php). Логика изменения файла и маркер `.vestnik-configured` написаны для нашего стенда: это не официальный скрипт и не требование OJS. Маркер однократной подготовки нужен, чтобы последующие старты не затирали параметры установщика.

```php
<?php
// Initialize the test configuration once. Preserve changes from the installer.
$path = '/var/www/html/config.inc.php';
$marker = '/var/www/html/.vestnik-configured';
if (file_exists($marker)) {
    exit(0);
}
$config = file_get_contents($path);
if ($config === false) {
    throw new RuntimeException('OJS configuration is missing');
}
$settings = [
    'general' => [
        'app_key' => '"base64:' . base64_encode(random_bytes(32)) . '"',
        'base_url' => '"http://localhost:8080"',
        'time_zone' => '"Asia/Novosibirsk"',
        'allowed_hosts' => "'[\"localhost\", \"127.0.0.1\"]'",
        'enable_beacon' => 'Off',
    ],
    'database' => [
        'driver' => 'mysqli',
        'host' => 'db',
        'username' => 'ojs',
        'password' => '"' . getenv('OJS_DB_PASSWORD') . '"',
        'name' => 'ojs',
    ],
    'files' => ['files_dir' => '/var/www/files'],
    'security' => [
        'salt' => '"' . bin2hex(random_bytes(32)) . '"',
        'api_key_secret' => '"' . bin2hex(random_bytes(32)) . '"',
    ],
    'email' => [
        'default' => 'smtp',
        'smtp' => 'On',
        'smtp_server' => 'mailpit',
        'smtp_port' => '1025',
    ],
];
foreach ($settings as $section => $values) {
    $pattern = '/(^\[' . preg_quote($section, '/') . '\]\s*\n)(.*?)(?=^\[|\z)/ms';
    $config = preg_replace_callback($pattern, function ($matches) use ($values) {
        $body = $matches[2];
        foreach ($values as $key => $value) {
            $line = '/^\h*;?\h*' . preg_quote($key, '/') . '\h*=.*$/m';
            if (preg_match($line, $body)) {
                $body = preg_replace_callback($line, fn() => "$key = $value", $body, 1);
            } else {
                $body .= "\n$key = $value\n";
            }
        }
        return $matches[1] . $body;
    }, $config, 1);
}
if (file_put_contents($path, $config) === false) {
    throw new RuntimeException('Could not save OJS configuration');
}
chown($path, 'www-data');
touch($marker);
echo "Local OJS configuration initialized.\n";
```

Этот файл при первом запуске меняет существующий `config.inc.php`: базу, SMTP, адрес, часовой пояс и каталог рукописей. Секреты создаются случайно. Маркер `.vestnik-configured` предотвращает повторное затирание настроек установщика. Файлы рукописей размещены в `/var/www/files`, вне публичного каталога Apache.

Фактически аккаунты создали штатным **UserImportExportPlugin**: экспортировали существующие определения ролей, подготовили XML, проверили его по схеме OJS и импортировали. Прямых изменений таблиц БД не делали. У двух рецензентов общие интересы; один совмещает роли рецензента и члена редколлегии.

**Альтернатива импорту:** приглашение через Settings → Users & Roles → Users → Invite to Role и регистрация по письму в Mailpit. Этот путь позволяет обойтись без генератора XML; отдельно целиком его не проверяла.

**Подготовка XML:** использовала базовый экспорт пользователей/ролей штатного Users XML Plugin в Tools → Import/Export. Сохранённый файл нужен скрипту как `/tmp/vestnik-users-base.xml`. Пароли тестовых аккаунтов находятся в закрытых локальных JSON, в отчёт не включены.

Листинг использованного `docker/import-full-users.php` (Славься чат джибити). Это наш генератор тестового XML, а не код плагина: читает экспорт и JSON аккаунтов, создаёт пользователей и проверяет их по схеме `lib/pkp/plugins/importexport/users/pkp-users.xsd` из OJS. Без него возможно подготовить XML вручную либо воспользоваться приглашениями:

```php
<?php
$ns='http://pkp.sfu.ca';$d=new DOMDocument();$d->load('/tmp/vestnik-users-base.xml');$users=$d->getElementsByTagNameNS($ns,'users')->item(0);while($users->firstChild)$users->removeChild($users->firstChild);
$add=function($p,$n,$v,$a=[])use($d,$ns){$e=$d->createElementNS($ns,$n);$e->appendChild($d->createTextNode($v));foreach($a as$k=>$val)$e->setAttribute($k,$val);$p->appendChild($e);return$e;};
foreach(json_decode(file_get_contents('/tmp/full-users.json'),true)as$a){$u=$d->createElementNS($ns,'user');$users->appendChild($u);foreach(['ru','en']as$l)$add($u,'givenname',$a['givenName'],['locale'=>$l]);foreach(['ru','en']as$l)$add($u,'familyname',$a['familyName'],['locale'=>$l]);$add($u,'country','RU');$add($u,'email',$a['email']);$add($u,'username',$a['username']);$p=$add($u,'password','',['is_disabled'=>'false','must_change'=>'false','encryption'=>'bcrypt']);$add($p,'value',password_hash($a['password'],PASSWORD_BCRYPT));$add($u,'date_registered','2026-10-12 00:00:00');$add($u,'date_validated','2026-10-12 00:00:00');$add($u,'locales','ru:en');foreach($a['roles']as$r){$m=$add($u,'user_user_group','');$add($m,'user_group_ref',$r);$add($m,'date_start','2026-10-12 00:00:00');$add($m,'masthead','false');}if(in_array('Reviewer',$a['roles']))$add($u,'review_interests','информационные технологии:алгоритмы');}
if(!$d->schemaValidate('/var/www/html/lib/pkp/plugins/importexport/users/pkp-users.xsd'))throw new Exception('invalid');$d->save('/tmp/full-users.xml');echo "XML valid\n";
```


**Результат:** в Users & Roles видны 11 аккаунтов с нужными ролями. Для смены роли в UI использовала Login As; API-утечку проверила отдельной собственной сессией рецензента, без прав администратора.

## 10. Выполнила сокращённый прогон
