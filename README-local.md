# Локальный стенд OJS

Состав: OJS 3.5.0-5 (AMD64, через эмуляцию в ARM64 Colima), MariaDB 11.8,
Mailpit. Порты привязаны только к 127.0.0.1.

При первом запуске Apache под эмуляцией завершался с ошибкой
`Couldn't create the mpm-accept mutex`. Настройка `docker/apache-local.conf`
переключает блокировки на `fcntl` и устраняет ошибку. Ядро OJS не изменялось.

```bash
colima start
docker compose up -d
docker compose ps
```

- OJS: http://localhost:8080
- Mailpit: http://localhost:8025

## Первичная установка

На текущем стенде установка уже завершена. Вход администратора проверен.
Логин: `admin`; пароль и тестовая почта сохранены в `.local-admin.json`,
который исключён из Git. Основная локаль — `ru`, дополнительная — `en`,
часовой пояс — `Asia/Novosibirsk`.

Создан только локальный тестовый журнал «Тестовый журнал Вестник» /
«Vestnik Test Journal»: http://localhost:8080/vestnik-test
Основной язык русский; русский и английский включены для интерфейса,
форм, подачи и метаданных. Контактная почта: `editor@example.test`.

Тестовые аккаунты: `editor`, `author`, `reviewer1`, `reviewer2`.
Пароли и роли сохранены в `.local-test-users.json` (исключён из Git).
Рецензирование — двойное слепое, требуется 2 рецензии; файлы доступны
рецензентам после согласия на приглашение.

Инструкция ниже нужна при создании нового стенда с пустыми томами.

Откройте OJS и заполните форму установщика:

- Создайте учётную запись администратора с тестовой почтой, например admin@example.test.
- Основной язык: русский; дополнительный: английский (если доступны в форме).
- Каталог загружаемых файлов: `/var/www/files`.
- Драйвер базы: MySQLi / mysqli.
- Сервер базы: `db`.
- Пользователь и название базы: `ojs`.
- Пароль базы: значение `OJS_DB_PASSWORD` из локального `.env`.
- Отключите создание новой базы: она уже создана контейнером MariaDB.
- Отключите передачу статистики PKP (Beacon).

Почта настроена на SMTP Mailpit, порт 1025, без авторизации и TLS.
Тестовые письма просматриваются в Mailpit.

Пароли базы созданы случайно, `.env` исключён из Git. На другой машине
скопируйте `.env.example` в `.env` и задайте два разных случайных пароля.

## Остановка и данные

```bash
docker compose stop
docker compose up -d
docker compose logs --tail=80 ojs
```

Постоянные тома содержат базу, приложение с конфигурацией и публичными файлами,
приватные рукописи и письма. Обычный `docker compose down` сохраняет тома.
Не используйте `docker compose down -v`, если нужны данные: флаг `-v` удаляет их.

Стенд предназначен для прогона редакционного сценария. Версия OJS зафиксирована;
том приложения сохраняет и код, поэтому обновление образа само по себе не
обновляет приложение. Обновление требует отдельной процедуры с бэкапом и миграцией.
